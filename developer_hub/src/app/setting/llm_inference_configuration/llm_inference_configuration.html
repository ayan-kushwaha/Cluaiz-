Hardware & Execution

GPU Layers (n_gpu_layers) Determines how many transformer layers are offloaded to the GPU. -1 offloads all layers for maximum speed, while 0 forces CPU-only execution.
No MMAP (no_mmap) Disables memory-mapped file I/O. Enabling this forces the model to load entirely into RAM, bypassing disk swap for faster inference.
Override Tensor (override_tensor) Applies regex-based rules to force specific tensors (e.g. FFN layers) to run on CPU instead of GPU, useful for fine-grained VRAM management.
Batch Size (batch_size) The number of tokens processed simultaneously during prompt evaluation. Higher values increase speed but consume more VRAM.
UBatch Size (ubatch_size) Micro-batch size for evaluation. Modifying this helps balance GPU compute load during heavy continuous batching.
Cache Type K (cache_type_k) Quantization format for the Key cache. Compressing to 'q8_0' or 'q5_0' saves massive amounts of VRAM with negligible quality loss.
Cache Type V (cache_type_v) Quantization format for the Value cache. Lower precision formats allow for significantly larger context windows.
Parallel Sequences (parallel) Maximum number of parallel sequences the engine can decode simultaneously. Essential for handling concurrent chat requests.
Speculative Type (spec_type) Speculative decoding algorithm (e.g. draft-mtp, ngram-mod) used to guess upcoming tokens and drastically increase generation speed.
Speculative Draft Max (spec_draft_n_max) The maximum number of tokens the draft model is allowed to predict ahead of the main model.

Templating Flags

Chat Template File The Jinja2 template file used to format the conversation history before passing it to the model (e.g. froggeric_fix.jinja).
Chat Template Kwargs Additional JSON arguments passed into the Jinja template to control internal rendering logic (e.g. {"preserve_thinking": true}).
Enable Jinja (jinja) Enables the Jinja2 templating engine for processing the chat template. Disabling it falls back to basic string concatenation.
Fit (fit) Controls how the sequence context window fits or truncates overflowing tokens when the conversation exceeds maximum context length.

ONNX Hardware & Execution

Hardware Offload Choose where to run the ONNX model. The engine automatically picks the best driver (CUDA, ROCm, etc.) for GPU.
Intra-Op Threads Number of threads used to parallelize the execution within a single operator (e.g. matrix multiplication). 0 means auto-detect.
Graph Optimization Level Controls the aggressiveness of ONNX graph fusions and simplifications. ORT_ENABLE_ALL provides the best performance.
Enable Profiling Generates detailed execution profiles for operators. Keep off during normal usage to prevent disk bloat.

Memory & Hardware Control

Inter-Op Threads Number of threads used to parallelize the execution of independent operators across the graph.
Enable Memory Pattern Optimizes the memory layout pattern for intermediate tensors, reducing allocation overhead during inference.
Enable CPU Memory Arena Utilizes an arena-based allocator for CPU memory, significantly speeding up memory allocations and reducing fragmentation.
Execution Mode Determines if operators are executed sequentially or in parallel. ORT_SEQUENTIAL is usually safer and faster for LLMs.
GPU Memory Limit Bytes Hard limit on the amount of VRAM the ONNX session can allocate. Set to 0 for unlimited access.
Arena Extend Strategy Strategy used when the memory arena runs out of space. 'kNextPowerOfTwo' allocates memory in exponentially larger chunks.

Quantization & Graph Transformer

Enable ORT Transformers Opt. Enables highly specialized fused operators (like MultiHeadAttention) designed specifically for Transformer models.
KV Cache Data Type The precision of the Key-Value cache. 'ort_fp16' halves memory usage compared to fp32, vital for long context ONNX inference.
Use Deterministic Compute Forces algorithms to use deterministic mathematical operations, ensuring identical outputs at the cost of some execution speed.

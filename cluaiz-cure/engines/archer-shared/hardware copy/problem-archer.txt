PROBLEM 1 — KHATARNAK (SEVERITY: CRITICAL)
File: memory.rs
══════════════════════════════════════════════════════════════

EXACT CRIME (Line 103-130):

    if cfg!(target_os = "macos") {                    ← LAYER 1 ka kaam LAYER 2 kar raha hai
        Command::new("sysctl")...                     ← OS command Layer 2 mein kya kar raha hai?
    }
    if Path::new("/etc/nv_tegra_release").exists() {  ← Jetson path check LAYER 2 mein
    }
    if Path::new("/proc/device-tree/model").exists() { ← Pi check LAYER 2 mein
        fs::read_to_string("/boot/config.txt")        ← Linux path LAYER 2 mein
    }

WHY IT BREAKS EVERYTHING:
  memory.rs ka kaam sirf hai: Blocks allocate karna, snapshot format karna.
  memory.rs ko OS ka naam pata hona hi nahi chahiye.
  Kal agar Jetson ka path badal gaya (/etc/nv_tegra_release_v2) to tum
  memory.rs mein dhundoge, linux_sensor.rs mein nahi — confusion guaranteed.

EXACT FIX:
  Step 1: SiliconProvider trait mein ek naya method add karo:
    fn capture_memory_state(&self) -> MemorySnapshot;

  Step 2: linux_sensor.rs mein implement karo:
    fn capture_memory_state(&self) -> MemorySnapshot {
        let mut is_unified = false;
        // Jetson check
        if Path::new("/etc/nv_tegra_release").exists() { is_unified = true; }
        // Pi check
        if Path::new("/proc/device-tree/model").exists() { is_unified = true; }
        MemorySnapshot { is_unified, ... }
    }

  Step 3: darwin_sensor.rs mein implement karo:
    fn capture_memory_state(&self) -> MemorySnapshot {
        let mut is_unified = false;
        if let Ok(out) = Command::new("sysctl").args(["-n","hw.optional.arm64"]).output() {
            if String::from_utf8_lossy(&out.stdout).trim() == "1" { is_unified = true; }
        }
        MemorySnapshot { is_unified, ... }
    }

  Step 4: memory.rs ki capture_snapshot() seedha call karegi:
    pub fn capture_snapshot(&self) -> MemorySnapshot {
        get_provider().capture_memory_state()   // BAS. Koi OS nahi, koi path nahi.
    }

PROBLEM 6 — MEDIUM (SEVERITY: MODERATE)  
File: scheduler.rs
══════════════════════════════════════════════════════════════

EXACT CRIME (Line 41-48):

    #[cfg(target_os = "windows")]
    return ComputeBackend::Cuda;    ← Windows = CUDA assume kar liya

    #[cfg(target_os = "macos")]
    return ComputeBackend::Metal;

    #[cfg(target_os = "linux")]
    return ComputeBackend::Vulkan;

WHY IT BREAKS:
  Scheduler.rs = Layer 3 (Manager). Isko OS ke basis par decide karna GALAT.
  Windows pe AMD GPU ho sakta hai (Vulkan, woh CUDA nahi).
  Linux pe NVIDIA GPU ho sakta hai (CUDA available, Vulkan nahi needed).
  Decision OS se nahi, actual hardware capabilities se hona chahiye.

EXACT FIX:
  Scheduler ko SovereignProfile ka compute.has_cuda, has_vulkan check karna chahiye:
    if metrics.vram_pressure < 80 {
        if profile.compute.has_cuda { return ComputeBackend::Cuda; }
        if profile.compute.has_metal { return ComputeBackend::Metal; }
        return ComputeBackend::Vulkan; // Default GPU path
    }
  Ye OS-independent, hardware-reality-based routing hai.
